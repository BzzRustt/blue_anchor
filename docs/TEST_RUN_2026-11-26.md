## Bugs found and fixed by this testing

1. **Paid event publishing could never complete** (also in `main`): after creating the Stripe session the app saves its id on the purchase, but the database role only had SELECT and INSERT, so the page crashed with "permission denied". Fixed with a one-column grant plus a policy limited to the organiser's own pending purchase (status, capacity and amount stay webhook-only). Verified by 3 new real-database checks.
2. Four pages scrolled sideways on phones (home, plans, profile, QR). Fixed.
3. Pro activation now requires the Pro price; refund and expiry handling added (see below).

## Apply to production (your decision, I have not touched production)

Bug 1 is a **database permission change** in `lib/db/rls.sql`. It takes effect only after `npm run db:rls` is run against the production database. Until then, paid event publishing fails in production for the same reason it failed here. Please review and apply it yourself (the dispatch rules forbid me from touching production).

## Refund rule (my choice; please veto if wrong)

- Full refund before the event starts: back to draft (organiser pays again to republish), or capacity drops to the largest remaining paid purchase. Registrations are kept.
- After it has started: stays published; only the purchase is marked refunded.
- Partial refunds change nothing. Pro follows the subscription, not refunds.
- Abandoned checkout (session expired): the pending purchase is marked failed.
