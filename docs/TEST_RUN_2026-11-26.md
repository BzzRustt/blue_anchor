## Refund decision (my choice, please veto if wrong)

- Full refund of an event payment **before the event starts**: the event returns to draft (organiser pays again to republish), or drops to the largest remaining paid capacity. Existing registrations are kept.
- **After it has started:** the event stays published so attendees keep their conversations; only the purchase is marked refunded.
- Partial refunds change nothing. Pro follows the subscription, not refunds.
- Abandoned checkout (session expired): the pending purchase is marked failed.
- Verified by unit tests (mocked) and by the real database checks.

3. Event messages on the owner's inbox show only the first answer in the list; the full text is in the detail view (unchanged behaviour).
