## Stripe review (read from code)

- Pro changes are re-checked with Stripe before acting. Late or out-of-order events cannot wrongly switch Pro on or off.
- The success page redirect only shows a message. It grants nothing; Pro comes from the verified webhook.
- Event publishing happens only in the webhook. Price is chosen on the server from the package table.
- Webhook signatures are checked over the raw body with a 5-minute tolerance.
- Duplicate events: the SQL functions are idempotent by design. This has **not** been run against a database yet.

### Gaps found (not fixed; each needs a product decision)

1. **Refunds are not handled.** If an event payment is refunded in Stripe, the event stays published. Decide: unpublish, or leave it.
2. **Abandoned checkouts** leave the event purchase as pending. Harmless (the organiser can retry), but there is no cleanup.
3. **Photo QR download gate is in the browser only.** The PNG is generated on the client, so the Pro check is a user-interface gate, not an enforced one. Enforcing it would mean rendering on the server.
